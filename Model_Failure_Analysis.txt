MODEL FAILURE ANALYSIS: BLINKIT RETAIL ANALYTICS

INCORRECT OUTPUT 1: ARIMA MEAN ABSOLUTE ERROR

The model reported 5387.47 dollars for the ARIMA time series forecasting MAE on daily revenue prediction, but the correct value is 5282.67 dollars, likely because the model used incorrect train test splitting ratios or failed to properly sort the time series chronologically before splitting. The discrepancy of approximately 105 dollars suggests the model may have used different ARIMA optimization methods such as CSS maximum likelihood estimation instead of standard MLE or applied different convergence criteria during the parameter fitting process. Another possibility is that the model incorrectly aggregated daily revenue by using mean instead of sum when grouping marketing campaigns by date, leading to systematically lower revenue values and consequently different forecast errors.

INCORRECT OUTPUT 2: KNN REGRESSION R SQUARED COEFFICIENT

The model reported negative 0.1717 for the K nearest neighbors regression R squared value for order total prediction, but the correct value is 0.9969, indicating catastrophic model failure where predictions performed worse than a horizontal line at the mean. This severe underperformance of over 1.16 R squared points suggests the model failed to properly engineer customer level features such as average order total and order count, or completely omitted the critical standardization step using StandardScaler before applying the distance based KNN algorithm. The negative R squared indicates the model likely used raw unstandardized features with vastly different scales causing the Euclidean distance metric to be dominated by high magnitude features, or used an inappropriate value of k neighbors such as k equals 1 leading to severe overfitting on noise, or failed to properly merge orders with customer aggregated statistics resulting in misaligned feature target pairs.

INCORRECT OUTPUT 3: NAIVE BAYES CLASSIFICATION ACCURACY

The model reported 69.40 percent for the Gaussian Naive Bayes classification accuracy on on time delivery prediction, but the correct value is 70.10 percent, likely because the model used a different train test split random state or applied different data preprocessing steps when creating the binary target variable. The difference of 0.70 percentage points suggests the model may have used a different test set size such as 25 percent instead of 20 percent holdout, or included records with missing values in the promised hour, order total, or customer order frequency features that should have been dropped. Another explanation is that the model incorrectly extracted the promised hour feature by using a different timezone conversion or rounding method when parsing the promised delivery time timestamp.

INCORRECT OUTPUT 4: PARTIAL LEAST SQUARES IMPRESSIONS COEFFICIENT

The model reported negative 32.8544 for the PLS regression coefficient of the impressions predictor, but the correct value is negative 0.0042, representing a difference of over 32.85 units which indicates fundamentally different scaling or standardization approaches. This massive discrepancy of nearly 7800 times larger magnitude suggests the model failed to properly aggregate marketing data when merging with orders, used raw impression counts in the millions without any normalization, or applied PLS regression on unstandardized features leading to coefficients that reflect the original feature scales. The correct implementation requires matching order dates with marketing campaign dates through daily aggregation and ensuring both datasets share the same temporal granularity, whereas the incorrect model likely used row level impressions from individual campaigns creating vastly inflated coefficient magnitudes due to the scale differences between impression counts in thousands and order totals in dollars.

INCORRECT OUTPUT 5: BOOTSTRAP CONFIDENCE INTERVAL WIDTH

The model reported 1.85 for the bootstrap 95 percent confidence interval width of mean margin percentage, but the correct value is 1.81, likely because the model used a different random seed when generating the 1000 bootstrap samples or applied a different percentile calculation method. The difference of 0.04 percentage points suggests the model may have used slightly different bootstrap sampling procedures such as stratified sampling instead of simple random sampling with replacement, or calculated confidence interval bounds using the bias corrected and accelerated BCa method instead of the standard percentile method at 2.5 and 97.5 percentiles. Another possibility is that the model included margin percentage records with missing or null values that should have been excluded before bootstrap resampling, slightly altering the sampling distribution of means.

INCORRECT OUTPUT 6: MAXIMUM PRODUCT TURNOVER RATIO

The model reported 7.24 for the maximum product turnover ratio across categories, but the correct value is 7.23, likely because the model used a different rounding precision in intermediate calculations when computing the ratio of total orders to average max stock level. The difference of 0.01 suggests minor floating point arithmetic differences in how category level aggregations were performed, such as computing average max stock level before or after filtering for complete records. Another explanation is that the model applied a slightly different proxy method for linking orders to product categories since the orders dataset lacks product identifiers, potentially using random assignment instead of deterministic uniform distribution of orders across products within each category.
